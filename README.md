# Filekit (Node.js)

Free PDF and image tools that run entirely in the browser. The Node.js server only
serves the page and its libraries. It has no upload endpoint, so your files are never
sent to the server.

## Run it

Requires Node.js 20 or newer.

```bash
npm install        # installs the libraries and builds public/vendor (runs automatically)
npm start          # http://localhost:3000
```

Change the port with `PORT=8080 npm start`.

## Project layout

- `server.js` - static file server (no dependencies, Node built-ins only)
- `public/index.html` - the Filekit page
- `public/vendor/` - browser builds of pdf-lib, JSZip and pdf.js (generated by `npm install`)
- `scripts/build-vendor.mjs` - copies and bundles the libraries into `public/vendor`
- `scripts/polyfill.mjs` - small polyfill that pdf.js 5 needs in older browsers

After changing a library version in `package.json`, run `npm run build:vendor`.

## Privacy

- Every tool reads and writes files in the browser. Nothing is uploaded.
- The server only answers GET and HEAD requests for files in `public/`.
- The page loads one external resource: Google Fonts (Inter). Remove the `<link>`
  in `public/index.html` if you want zero external requests.

## Deploying

This is a standard Node app, so it runs on any host that runs Node (for example
Render, Railway, Fly.io or a VPS behind nginx). Set the start command to `npm start`.
Because no uploads are received, you do not need file storage or cleanup jobs.

## Third-party libraries

- pdf-lib (MIT) - PDF editing
- pdf.js / pdfjs-dist (Apache-2.0) - PDF rendering
- JSZip (MIT or GPLv3) - ZIP packaging
- esbuild (MIT) - build-time bundling only
